# Requisitos Funcionales

## Aplicación móvil de gestión comercial de mayoristas de papa

Los siguientes requisitos funcionales definen las principales capacidades que debe proporcionar el sistema para apoyar la gestión comercial de los comerciantes mayoristas de papa.

| Proceso | Código | Requisito funcional |
|---|---|---|
| Acceso | RF01 | El sistema debe permitir el acceso mediante credenciales individuales para el mayorista y el encargado. |
| Acceso | RF02 | El sistema debe permitir al mayorista acceso total y restringir al encargado sustituto a las funciones de pesaje, compras y ventas. |
| Catálogos | RF03 | El sistema debe permitir gestionar clientes y proveedores con información de contacto, ubicación, crédito y estado. |
| Catálogos | RF04 | El sistema debe permitir gestionar productos por variedad, calidad, procedencia, presentación, unidad de medida y precio referencial. |
| Recepción | RF05 | El sistema debe permitir registrar fecha, proveedor, teléfono, vehículo, conductor y variedades antes de la descarga. |
| Recepción | RF06 | El sistema debe permitir registrar consecutivamente el peso de cada saco y asociarlo con la variedad correspondiente. |
| Recepción | RF06A | El sistema debe mostrar los sacos, peso y promedio por variedad y del cargamento completo, y permitir correcciones autorizadas. |
| Recepción | RF06B | El sistema debe permitir cerrar el pesaje, calcular tara y peso neto, conservar el detalle individual y crear el lote correspondiente. |
| Compras | RF07 | El sistema debe permitir registrar precio, flete, adelantos, descuentos y calcular el monto líquido del proveedor. |
| Inventario | RF08 | El sistema debe actualizar las existencias a partir de ingresos, ventas, devoluciones, mermas y ajustes. |
| Inventario | RF09 | El sistema debe permitir consultar el stock por variedad, calidad, presentación, lote y antigüedad. |
| Ventas | RF10 | El sistema debe permitir registrar ventas y despachos con destino, vehículo, flete y forma de pago. |
| Ventas | RF11 | El sistema debe permitir registrar precios negociados y descuentos dentro de los límites establecidos. |
| Ventas | RF12 | El sistema debe permitir generar un comprobante interno o resumen del pedido para compartir digitalmente. |
| Cuentas | RF13 | El sistema debe gestionar créditos de clientes, vencimientos, abonos, saldos y compromisos de pago. |
| Cuentas | RF14 | El sistema debe gestionar cuotas del proveedor, vencimientos, abonos y cancelaciones. |
| Caja | RF15 | El sistema debe registrar pagos, cobros y la liquidación diaria de flete y estiba. |
| Alertas | RF16 | El sistema debe generar avisos de vencimientos, bajo stock y operaciones pendientes. |
| Reportes | RF17 | El sistema debe permitir consultar compras, ventas, utilidad, costos, stock y cuentas. |
| Analítica | RF18 | El sistema debe permitir analizar la evolución de precios por producto, relación comercial y periodo. |
| Inteligencia Artificial | RF19 | El sistema debe identificar patrones y generar una estimación semanal cuando el historial sea suficiente. |
| Inteligencia Artificial | RF20 | El sistema debe mostrar rango, fecha, variables, nivel de confianza y comparación con el valor real. |
| Móvil | RF21 | El sistema debe permitir registrar operaciones temporalmente sin conexión y sincronizarlas posteriormente. |
| Auditoría | RF22 | El sistema debe registrar el usuario, fecha y detalle de cada cambio o anulación realizada. |
| Notificaciones | RF23 | El sistema debe generar recordatorios de pagos, cobranzas, stock y pedidos. |
